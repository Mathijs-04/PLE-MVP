# Data

Rules data layout, import pipeline, and markdown format. All documentation lives here — nothing is annotated inside `data/` itself.

## Folder Layout

| Path | Contents | Git status |
|------|----------|------------|
| `data/datafiles-WH40K/` | 40K faction and core rules markdown (RAG source) | Tracked |
| `data/datafiles-WHAOS/` | AoS faction and core rules markdown (RAG source) | Tracked |
| `data/datafiles-PDF/` | Source PDFs (if present) | Reference only |
| `data/datafiles-Tags/` | Tag-to-page JSON for PDF deep links | Tracked |
| `data/bsdata-import-manifest.json` | BSData import run metadata | Tracked |
| `public/rulebooks/` | PDFs served to the UI | Tracked |
| `python/indexes/` | FAISS vector indexes | Gitignored |

Indexes are generated locally and must be rebuilt after cloning or updating markdown files. See [setup.md](setup.md).

## Markdown Format Contract

Faction markdown files follow a structure enforced by `python/tests/test_bsdata_importer.py`:

- `# Faction Name` as the document title
- `## Units` section containing unit entries
- `### Unit Name` for each unit
- Profile line with stats: `**Points:**`, `**M:**`, `**T:**`, etc.
- `**Keywords:**` line per unit
- Weapon and ability tables where applicable
- Optional `## Points Table` section (generated by `generate_points_tables.py`)

Example (abbreviated):

```markdown
# Space Marines

## Units

### Captain
**Points:** 80 | **M:** 6" | **T:** 4 | **SV:** 3+ | **W:** 5 | **LD:** 6+ | **OC:** 1
**Keywords:** Character, Infantry, Adeptus Astartes

#### Ranged Weapons
| Name | Range | A | BS | S | AP | D | Keywords |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Bolt pistol | 12" | 1 | 2+ | 4 | 0 | 1 | Pistol |
```

## Data Pipeline Scripts

| Script | Purpose |
|--------|---------|
| `python/update_rules_from_bsdata.py` | Fetch BSData catalogs, convert to markdown, rebuild indexes |
| `python/build_index.py` | Rebuild FAISS indexes from existing markdown |
| `python/bsdata_importer.py` | Core import logic (not run directly in normal workflows) |
| `python/generate_points_tables.py` | Regenerate `## Points Table` sections from unit data |

BSData source repositories:

- 40K: `BSData/wh40k-10e` → `data/datafiles-WH40K/`
- AoS: `BSData/age-of-sigmar-4th` → `data/datafiles-WHAOS/`

## Common Workflows

**Fresh clone — build indexes from existing markdown:**

```bash
python python/build_index.py --game aos --game wh40k
```

Requires `OPENAI_API_KEY`.

**Update faction data from BSData and rebuild indexes:**

```bash
python python/update_rules_from_bsdata.py --game wh40k
python python/update_rules_from_bsdata.py --game aos
```

Both games can be passed in one run:

```bash
python python/update_rules_from_bsdata.py --game wh40k --game aos
```

**Import markdown without rebuilding indexes:**

```bash
python python/update_rules_from_bsdata.py --game wh40k --skip-index
```

Useful when you only need updated markdown and will rebuild indexes separately.

**Preview import without writing files:**

```bash
python python/update_rules_from_bsdata.py --game wh40k --dry-run
```

**Regenerate points tables across all faction files:**

```bash
python python/generate_points_tables.py
```

**Rebuild indexes only (after manual markdown edits):**

```bash
python python/build_index.py --game wh40k
python python/build_index.py --game aos
```

See also [architecture.md](architecture.md) for how indexed data is used at query time.
